## Research and implications

- [Notion editing basics](https://www.notion.com/en-gb/help/writing-and-editing-basics) documents margin block handles, slash commands and selection formatting. Its actual public editing demonstration was opened and inspected (`reference-notion-editing.jpg`). Implication: keep block structure while letting normal writing read as a continuous document, with tools close to the active block.
- [Notion sidebar](https://www.notion.com/help/navigate-with-the-sidebar) emphasizes organization, quick access and nested pages. Implication: page navigation must receive substantial, stable space; global features should not displace most of the tree.
- [OneNote navigation](https://support.microsoft.com/en-gb/onenote/onenote-help-and-learning/navigate-your-notes-with-onenote) separates notebooks/sections/pages and allows navigation to collapse for focused work. The official navigation screenshot was inspected (`reference-onenote-navigation.jpg`). Implication: give persistent places and transient working context distinct visual roles; avoid copying the entire Office ribbon into a web editor.
- [Obsidian workspace](https://obsidian.md/help/workspace) distinguishes document tabs, collapsible sidebars, ribbon and status information, including different mobile arrangements. Its help surface was inspected (`reference-obsidian-workspace.jpg`); this is documentation evidence, not a test of the installed desktop app. Implication: retain working tabs and local context without making every tool permanently visible.
- [Coda page customization](https://help.coda.io/hc/en-us/articles/39555952327437-Customize-the-pages-of-your-doc) describes contextual page options and separate table-page treatment. The search service returned this documentation, but the live 2025-refresh article redirected to a Superhuman Help Center 404. Do not claim a live Coda application audit or current visual capture. Use the documented contextual pattern, not an invented Coda screenshot.
- [Progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) informs showing frequent actions first while retaining discoverable access to secondary actions. This does not justify hiding essential controls behind hover alone.
- [Aesthetic-usability effect](https://www.nngroup.com/articles/aesthetic-usability-effect/) distinguishes perceived attractiveness from effective use; attractive visuals can hide usability defects in evaluations. Test task performance and recovery separately from visual polish.
- [Hassenzahl, Kekez and Burmester](https://www.attrakdiff.de/files/wwdu02_hassenzahl_print.pdf) distinguish pragmatic and hedonic contributions to appeal and their dependence on usage. Apply this as a design lens, not evidence that an untested interface makes users happier. Here the intended qualities are clarity, a recognizable writing environment, confidence in saved work and satisfying direct manipulation.
- [WCAG 2.2 target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) supplies the minimum target/spacing criterion. The project will use comfortably sized touch targets, visible keyboard focus and measured contrast; no full accessibility-compliance claim follows from this audit.

## Design constraints

Latest explicit user steering: no green application palette and no serif typography. The generated Quiet Workspace direction is rejected. Studio Index is selected by the implementer under the existing no-questions instruction: its activity rail separates tools from a generous page tree while retaining horizontal working tabs and a continuous writing surface. Replace its generated green status chips and any button gradient; neither overrides the user's constraint. Focus Desk explored vertical working tabs but duplicates more page lists and displaces tree space. No concept has been described as user-approved.

English product copy; Brazilian Portuguese chat. Existing React/TypeScript architecture, one Zustand application-state owner, canonical page/database/Yjs ownership, one authored CSS entry. No new fake dashboards, metrics, AI actions, avatars, placeholder buttons or decorative document content. Preserve actual user notes, permissions, recovery and working tabs. Regular document blocks remain continuous, with no paragraph cards or large inter-block gaps. Spatial canvas remains a separate capability.

Before product code changes: generate three independent full-screen directions grounded in the actual captured product, compare them against these findings, select a direction autonomously under the user's explicit no-questions instruction, and record a concrete token/component/responsive specification. This is developer selection, never described as user approval. Then implement the same visual system across writing, navigation, tables, inspector, command/search surfaces, spatial tools and mobile states, with rendered comparisons and interaction regressions.
# Neutral-shell checkpoint, 2026-11-08

Fresh IAB screenshots `interface-implementation/writing-neutral-1487.jpg` and `writing-neutral-390.jpg` were captured and their physical dimensions verified as 1487×1058 and 390×844. Both use Inter/Arial, actual `--accent: #45464e`, and have no document-level horizontal overflow. The source Studio Index concept and the desktop implementation were inspected together with `view_image`.

Comparison: the narrow activity rail, adjacent workspace/page tree, continuous writing surface, quieter page actions and sans-serif hierarchy follow the chosen structure. Graphite actions and selection intentionally supersede the generated violet concept per the user's later explicit neutral-color instruction. Existing page copy, native table data and authored content were retained. Account/sign-out remain visibly named in the navigation pane instead of the concept's anonymous rail avatar. The mobile toolbar is collapsed into reachable contextual actions; no formatting bar covers unfocused reading.

Remaining mismatches are acceptance work, not a visual signoff: desktop chrome still has too many small actions; the default file icon offsets an ordinary note title; page-link rows and embedded table typography are too small relative to prose; completed task text needs stronger contrast; whole-product table/inspector/dialog/graph/canvas consistency still needs inspection. The leading-blockquote TextSelection warning remains present. No claim of full application completion or 10/10 fidelity is made.

Fresh verification: typecheck and production web/server build passed; the build retains its 601.31 kB initial-chunk warning. All 21 focused browser scenarios passed in 1.8 minutes across interface productivity, page presentation/properties, recovery accessibility, templates and workbench flows. The earlier complete 70-scenario run had one canvas boundary-selection failure and has not been superseded by a green full run.

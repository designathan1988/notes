## Priorities and invariants

Implement the working context and direct interaction first, then editor depth and data views, followed by discussion/history, discovery/canvas and cross-surface integration. This order resolves the user's central complaint while preserving the full comparison inventory. Remaining rows stay explicitly unfinished until implemented and verified; completing the shell alone does not complete the goal.

Retain one Zustand application store. Tabs hold page IDs and route state, never body/title copies. PostgreSQL and Yjs remain authoritative for durable data. UI-only layout preferences are identity/workspace scoped. Each capability owns its server service, client slice and UI. Shared editor schema must support every persisted node across editor, import, export and search. All authored CSS stays in `styles.css`. Never alter existing user note content to make screenshots look complete.

The references establish interaction patterns, not a claim of total feature parity. Hosted operations, native packaging and external service provisioning remain tracked by the original staged architecture; no real invitations, payments or publication are authorized by this investigation.

### Page identity and reusable knowledge research

[Obsidian properties](https://obsidian.md/help/properties) demonstrates typed note metadata and property-aware search. [Notion database templates](https://www.notion.com/help/database-templates) combines initial property values with reusable page content, including media and subpages; prefilled relations intentionally keep references to their existing targets. These are interaction references rather than claims of complete feature parity.

The implementation will keep ordinary-page properties in that page's aggregate and database-record properties in their existing database owner. This preserves privacy boundaries and avoids a second record schema. Reusable page creation and retained local-draft recovery share one canonical instantiation command. Independent template media/internal-reference handling, rich metadata interchange and full record-page controls remain required acceptance work.

[Notion page customization](https://www.notion.com/help/customize-and-style-your-content) uses page icons for recognition and optional cover banners for page identity. The implemented presentation controls follow that contextual pattern: emoji selection, uploaded image covers with pointer or keyboard repositioning, and removable tags on the reading surface. Icons also appear in navigation and working tabs. Tags participate in indexed text discovery and exact tag filtering under the current page ACL.

Task 5 now has a working presentation and local-recovery foundation. Version 2 workspace archives carry icons, cover references and tags; version 1 imports remain supported. Cover bytes are included and their ownership references are remapped. Local drafts can be read and downloaded offline, and recovered into private pages online with exact-state acknowledgement. This does not complete Task 5: typed ordinary-page properties, complete canonical record-page properties and independent reusable templates remain open, followed by spatial tools and whole-product acceptance.

Typed properties now edit on the ordinary-page reading surface, including text, numbers, dates, select/multi-select, checkboxes, URLs, page relations, bounded formulas and explicit property actions. Schema changes are frozen to the opening revision; cell edits compare the original value and field definition even when a live refresh has supplied a newer aggregate revision. Archiving retains definitions and values. Page metadata has one canonical aggregate, with a bounded 64 KiB property payload and derived search/formula/link projections. ZIP interchange carries property schemas and values and remaps page relations.

Full record pages now load one canonical record directly, reuse the table/inspector property controls, and edit the owning database schema. They do not create a second page-property store or depend on the first table-results page. Normalized record merging preserves record values and page titles according to their separate revisions; stale navigation and single-record responses cannot repopulate superseded access results. Independent reusable templates and the remaining spatial/whole-product work are still open.

Reusable templates now have a real library, search/type filters, isolated previews, definition editing, direct blank creation, duplication and independent instantiation. Page trees copy authorized media and descendants; database templates copy native schemas, views and records; internal references remap while external references remain connected. Record-template defaults use the current owning database schema and retain invalid values for explicit review. Current-account copy intents survive an unknown response and reload without duplicating a confirmed result. Copy preflight refuses to omit retained unsynchronized source drafts. The plan records the complete verification gate; spatial discovery/canvas and whole-product acceptance remain separate unfinished requirements.

## Spatial graph implementation checkpoint

The graph comparison uses [Obsidian Graph view](https://obsidian.md/help/plugins/graph) as a behavioral reference: open notes by click, highlight connections, filter unlinked notes, explore a local neighborhood, and navigate with pointer or keyboard. These are reference behaviors, not a claim of feature parity. A force-based arrangement replaces the former fixed circle; directional links and the inspected note's incoming/outgoing references expose actual knowledge relationships.

[D3 simulation documentation](https://d3js.org/d3-force/simulation) requires disposable node/link inputs and recommends workers for expensive static layouts. A seven-run local measurement at the API's 180-node/500-edge bound measured 101.98 ms median and 130.28 ms maximum before moving calculation off the UI thread. The worker receives IDs, kinds and capped placeholder label lengths, returns coordinates only, terminates after its job, and cannot write pages. [Vite's worker integration](https://vite.dev/guide/features.html#web-workers) packages it independently. Its loading and failed/retry states preserve application navigation.

The existing workbench owner stores manual positions and camera preferences, scoped by account, workspace and window; no body, title or page revision changes when moving graph nodes. Search does not rearrange nodes. A single camera transform handles SVG coordinates, zoom anchors, keyboard panning, native two-pointer pinch and cancellation. Screen-space label collision checks preserve the active title without covering nearby circles. Graph discovery ranks only authorized endpoints, reports bounded/truncated results, and rejects cross-workspace or template-definition centers. Revoking a local center clears it and returns to the authorized global view.

This checkpoint covers derived graph discovery. The separate persisted spatial canvas, canonical collaboration/recovery/interchange integration, whole-product acceptance and commercial/native release gates remain unfinished.
